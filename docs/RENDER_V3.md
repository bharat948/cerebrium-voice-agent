# Deploy Voice Foundry v3 on Render

This setup requires **no tunnel or local always-on laptop**. Render provides public HTTPS/WSS hosting. Voice calling is sensitive to cold starts, so use an always-on paid web instance for live calling.

## 1. Repository

Push the project files to an authorized GitHub repository, excluding `.env`, database files and real contact data.

## 2. Blueprint

Create a Render **Blueprint** from the repository root. `render.yaml` provisions:

- `voice-foundry`: one Docker Web Service (`starter` plan; review cost before deployment).
- `voice-foundry-db`: managed PostgreSQL (`basic-256mb` plan; verify current plan availability/pricing).

The `DATABASE_URL` and `PUBLIC_BASE_URL` variables are provided by Render. Do not add a `/data` SQLite disk to this v3 configuration. Postgres/pgvector requires the database to support `CREATE EXTENSION vector`.

## 3. Secrets and Google OAuth

Render Environment requires:

- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` from a Google Cloud **web application OAuth client**.
- `GOOGLE_OWNER_SUB`: stable Google OIDC `sub` claim for your specific account, obtained through a verified OIDC login/identity-token inspection; do not use your email address in this field.
- `APP_API_KEY` and `SESSION_SECRET`: independent cryptographically random values generated by Render.
- `AUTH_MODE=google` and `APP_ENV=production`.

Register callback `https://YOUR-SERVICE.onrender.com/auth/google/callback` in Google Cloud authorized redirect URIs; add your app origin to authorized JavaScript origins when required. Complete Google OAuth consent-screen requirements. For a preproduction bootstrap, use a staging instance and verify the ID-token subject before allowing public traffic. Do not temporarily allow all Google users.

## 4. Phone credentials

Set Twilio, OpenAI and optionally Deepgram secrets in Render Environment. Default `DEMO_MODE=true` prohibits phone dialing. To enable a real call after authorized testing, use `DEMO_MODE=false`, register consenting recipients and configure `OWNER_PHONE` for private agents.

Twilio incoming webhook: `POST https://YOUR-SERVICE.onrender.com/twilio/voice`.

## 5. Background reports

To enable live research reports set `OPENAI_API_KEY`, `BRAVE_SEARCH_API_KEY` (recommended), and `SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`. Do not store OAuth access tokens or mail passwords in agent prompts. Research delivery requires `email_consent=true` and a registered email. Google News RSS is discovery-only, not full-article verification.

## 6. Validation and rollback

The container runs `alembic upgrade head` before starting the server. Run `/health` and `/docs`, create a test agent and contact, and conduct a short authorized voice test. Confirm that Postgres records persist across redeployments. Export a DB backup before migrating existing v2 data; do not delete the Render SQLite disk until a complete verified migration is signed off.

**Limits:** Current single-process WebSocket ownership and worker loop prohibit horizontal multi-instance scaling. See the implementation plan for cluster extraction.
